# Desktop UI Design Guidelines

## Scope

All UI generated by the agent is Desktop-first.

Optimize for:

- Large screens (1280px+)
- Mouse and keyboard interaction
- High information density
- Efficient workflows
- Professional software aesthetics

Do not optimize for mobile unless explicitly requested.

---

# 1. Desktop Layout Principles

Desktop screens provide abundant space.

Do not simply scale mobile layouts horizontally.

Prefer:

- Multi-column layouts
- Persistent navigation
- Side panels
- Split views
- Dense information organization

Avoid:

- Excessive empty space
- Giant cards
- Oversized buttons
- Mobile-style stacking

---

# 2. Page Structure

Most desktop pages should follow:

```

+------------------------------------------------+
| Header                                         |
+---------+--------------------------------------+
|         |                                      |
| Sidebar | Main Content                         |
|         |                                      |
|         |                                      |
+---------+--------------------------------------+

```

Typical structure:

- Left navigation
- Top toolbar/header
- Main content area
- Optional right detail panel

---

# 3. Container Rules

Desktop content should use controlled width.

Default:

```

max-width:
1200px - 1440px

```

For dashboards:

```

width:
100%

```

For reading/content:

```

700px - 900px

```

Avoid:

- Full-width text paragraphs
- Extremely narrow desktop layouts

---

---

# 5. Information Density

Desktop applications should maximize useful information.

Prefer:

- Tables
- Lists
- Side-by-side comparison
- Multi-column grids
- Detail panels

Avoid:

- Huge empty hero areas
- Excessive vertical scrolling
- One-card-per-screen layouts

---

# 6. Navigation

Desktop applications should use persistent navigation.

Preferred:

Sidebar:

```

width:
220px - 280px

```

Navigation rules:

- Group related items
- Highlight current location
- Keep hierarchy shallow

Avoid:

- Hamburger menus on desktop
- Hidden primary navigation

---

# 7. Dashboard Layout

Dashboard default:

```

Grid layout

2-4 columns depending on content

```

Example:

```

+---------+---------+---------+
| Metric  | Metric  | Metric  |
+---------+---------+---------+
| Chart             | Detail |
+-------------------+--------+
| Table                      |
+----------------------------+

```

---

# 8. Tables

Desktop tables are preferred for structured data.

Rules:

- Use tables instead of cards when comparing many records.
- Support:
  - sorting
  - filtering
  - pagination
  - selection

Avoid:

- Turning every row into a card
- Excessive row height

Recommended:

Row height:

```

40px - 56px

```

---

# 9. Panels and Split Views

Use split layouts when users need comparison.

Examples:

```

List        Detail

Projects    Project Info

Emails      Email Content

Files       Preview

```

Typical:

```

Left panel:
300-400px

Right panel:
remaining space

```

---

# 10. Typography

Desktop allows stronger hierarchy.

Recommended:

```

Page title:
32-40px

Section:
20-24px

Body:
14-16px

Dense UI:
13-14px

```

Do not make every element large.

Professional desktop software often uses smaller typography with clear hierarchy.

---

# 11. Cards

Use fewer cards than mobile.

Cards are for:

- grouping
- emphasizing
- separating contexts

Avoid:

```

Everything is a card

```

Bad:

```

Card
└ Card
└ Card

```

Prefer:

```

Section
├ Content
└ Actions

```

---

# 12. Forms

Desktop forms can use horizontal layouts.

Preferred:

```

Label        Input
Label        Input
Label        Input

```

For complex forms:

Use:

- sections
- tabs
- accordions
- side navigation

Avoid:

- extremely long single-column forms

---

# 13. Dialogs

Desktop dialogs should be used carefully.

Recommended widths:

Small:

```

400-500px

```

Normal:

```

600-800px

```

Large:

```

900px+

```

Avoid:

- mobile-sized dialogs centered on huge screens

---

# 14. Interaction

Desktop supports:

- hover
- keyboard shortcuts
- context menus
- drag and drop

Use them when helpful.

Examples:

- Hover reveals actions
- Cmd/Ctrl + K command palette
- Keyboard navigation

Do not hide important actions only behind hover.

---

# 15. Hover States

Every interactive element should have:

- hover state
- active state
- disabled state

Keep transitions:

```

150-200ms

```

---

# 16. Color Rules

Desktop enterprise/product UI should be restrained.

Use:

- Neutral background
- Clear contrast
- Limited accent colors

Avoid:

- Neon colors
- Excessive gradients
- Colorful dashboards

---

# 17. Shadows and Borders

Prefer:

- subtle borders
- light shadows

Avoid:

- floating everything
- heavy shadows

Desktop UI should feel stable and organized.

---

# 18. AI Interface Desktop Rules

For AI tools:

Prefer:

```

+-------------+----------------------+
| History     | Conversation         |
|             |                      |
|             |                      |
+-------------+----------------------+

```

Useful desktop patterns:

- Conversation sidebar
- Context panel
- Prompt history
- Result preview
- Tool execution panel

Avoid:

- Mobile chat bubble style
- Full-screen single column chat

---

# 19. Final Desktop Review Checklist

Before finishing:

Layout:

- [ ] Uses desktop space effectively
- [ ] Does not look like stretched mobile UI
- [ ] Navigation is accessible
- [ ] Information density is appropriate

Visual:

- [ ] Consistent spacing
- [ ] Limited colors
- [ ] Clear typography hierarchy
- [ ] Consistent components

Interaction:

- [ ] Hover states exist
- [ ] Loading states exist
- [ ] Empty states exist
- [ ] Keyboard/mouse interaction feels natural

Quality:

- [ ] No unnecessary cards
- [ ] No excessive whitespace
- [ ] No decorative UI without purpose

---

# Core Rule

Desktop UI should make users feel powerful.

Use the available screen space to reduce clicks,
increase visibility,
and improve workflow efficiency.
